# Domain docs

Use a single-context layout: `CONTEXT.md` at the repository root
and decisions under `docs/adr/`.

Before exploring the codebase, read `CONTEXT.md` if it exists and
any ADRs relevant to the work. If these files are absent, proceed
silently. Create domain documentation through domain-modeling only
when terms or durable decisions become settled.

Use the vocabulary defined in `CONTEXT.md`. If a needed concept is
missing, reconsider the wording or identify the gap for domain-modeling.

Surface conflicts with an existing ADR explicitly, identifying the
decision and the reason to reconsider it.
